# NEXUS | AZEROTH COMPANION — v7.9.1 Owner Deployment

## Why this release requires a Cloudflare step

The public Azeroth Companion on GitHub Pages cannot extend Battle.net login sessions or read private account collections by itself. Those features run through the separate **nexus-azeroth-api** Cloudflare Worker. Committing the updated Worker source to GitHub does **not** deploy it.

**Deployment source:** `azeroth-companion/backend/worker-v7.9.1-single.js`

This is a complete successor to the previously deployed v4 single-file Worker. Do **not** paste the short `account-persistence-v7.9.1.js` browser module into Cloudflare. Do **not** replace only a portion of the Worker; you need the full single-file source.

## Safe deployment

1. Open **Cloudflare → Workers & Pages → nexus-azeroth-api → Edit code**. Preserve a private backup or version rollback of the currently deployed Worker before editing.
2. Open `worker-v7.9.1-single.js` in GitHub, select **Raw**, copy the entire source, and replace only the Worker's **source code**.
3. Keep all existing encrypted secret bindings unchanged:
   - `BLIZZARD_CLIENT_ID`
   - `BLIZZARD_CLIENT_SECRET`
   - `AZEROTH_SESSION_SECRET`
4. Deploy the Worker. **Do not insert secrets directly in code or publish them to GitHub.**
5. Check that the original public Blizzard item, talent and character lookups still work. Confirm the private `/account` portal signs in via Battle.net and that `/account/verify-companion` returns correctly to Azeroth Companion.
6. Verify the new **My Unlocks & Collections** section while signed into the private portal: mounts, pets, toys, heirlooms and completed achievements (achievements require selecting one of your account characters).
7. Test a disconnected session, incorrect/expired authorization, and **Disconnect**. It should continue to remove access immediately on this browser.

**Do not deploy until you're ready to test:** the GitHub release can publish the read-only progress panel independently; the extended sessions and private collection explorer become active **only after** the new Cloudflare Worker deployment.

## Authentication and security rules

- The old private account session was capped at one hour. The new session is capped at **24 hours, or Blizzard's actual issued access-token expiration, whichever comes first**. If Blizzard grants a shorter token, the session remains shorter. Revocation and disconnect still take precedence.
- The separate public companion verification receipt is valid **at most 15 minutes**, down from the old two-minute window. It is an encrypted, time-limited status proof stored only in this browser tab's session storage. It is **not** a Battle.net login token.
- A longer server login session does not automatically turn a 15-minute receipt into permanent verification. Visitors can press **Verify Again** to recheck securely. Do not store Blizzard credentials or user tokens in the public website.
- No automatic OAuth refresh-token storage, long-lived token copying, or cross-site credential sharing has been added.
- Public local plans do not belong to the authenticated account cookie. Token expiry or disconnection does not delete Talent Forge drafts, Item Atlas, Loot Hunter, Character Targets, or the core Companion records. Browser storage removal or using a different device is different: export backups from **Data & Backup** before changing browsers or clearing site storage.

## What the unlock explorer can and cannot show

The private portal now makes **read-only on-demand** requests for the account's Blizzard-reported mounts, pets, toys and heirlooms and for completed achievements associated with a selected account character. It can list source-returned names and IDs and provides a local search of returned entries. Some account categories or regions might not return usable data. Results are bounded to 1,800 records per category and 120 displayed at once. If truncated, this is explicitly disclosed.

The website still **cannot inspect all equipped + unequipped bags, bank, reagent storage, warband bank, or every live currency balance**. Blizzard's public Battle.net web endpoints in this integration do not expose that complete live character inventory. We have not added fake inventory ownership or fabricated currencies. A future optional user-controlled WoW addon / SavedVariables import would be required for those details, subject to current retail addon API restrictions.

## Owner acceptance tests

- Battle.net sign-in, `wow.profile` authorization, Verify & Return and manual disconnect
- Proof valid for up to 15 minutes and rejects modified / expired receipts
- Private session never exceeds Blizzard access token lifetime and expires or rejects revoked tokens
- Previously saved Talent Forge builds, Item Atlas records, and local farming goals remain after verification expires
- Collections display source-returned data; missing or unavailable data is not labeled unowned
- Game lookups and original music/Founder controls still work on PC and iPhone
- No password, client secret, session token, refresh token or private data appears in GitHub commits, page URLs or public screenshots

This release's source-level checks are **not a substitute for live Cloudflare/Battle.net/browser tests**.

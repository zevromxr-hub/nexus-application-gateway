## New: Token Foundry (Studio 27)

An encrypted browser-local owner inventory for generating, managing and exporting product access codes, personal licenses and redemption codes.

### Generate tokens
- Create 128-bit, 192-bit and 256-bit cryptographically random tokens with editable prefixes.
- Organize issued tokens by product, purpose, recipient, label and private notes.
- Generate batches of up to 50 codes and keep an inventory of up to 5,000 records.
- Set optional expiration dates and on-device redemption limits.

### Private token management
- Initialize an AES-256-GCM encrypted owner vault using a passphrase.
- Unlock to view a searchable inventory of masked codes.
- Copy or reveal a selected code, filter by status and monitor usage.
- Validate codes against the local inventory, optionally recording a local redemption.
- Disable, re-enable and revoke codes individually or in bulk.
- Review an encrypted history of token changes.

### PC and iPhone exports
- Download or share encrypted JSON vault backups.
- Export owner inventories to CSV, code lists to TXT and newly generated token batches to CSV.
- Import an encrypted vault backup on another browser/device by entering its passphrase.
- Use separate export actions so mobile file sharing is triggered by a direct user tap.

## Access design

The Token Foundry's local passphrase locks **that device's encrypted token inventory**. A public static site is not protected by this feature. Real customer access to a hosted application requires a separate server-side login/license verification system; a Discord-shared URL alone does not authorize users.

The PROXIMUS site also requests that search engines not index the main application page. This is an indexing preference, not an access-control mechanism.
